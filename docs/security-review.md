# Проверка безопасности — 8 октября 2026

Область: исходный код приложения «Эврика» (клиент, контент-пайплайн, серверный обработчик синхронизации), зависимости npm, собранный production-бандл.

Методы: `npm audit`; поиск опасных паттернов (`dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function`, `localStorage`, `http://`); ручной разбор точек входа данных (параметры URL, формы, импорт контента, обмен с сервером, экспорт); проверка production-сборки в браузере с включённой CSP; новые автотесты.

## Что проверили — проблем нет

- **XSS.** Весь текст заданий, подсказок, решений и имён рендерится через React как текст; `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function` в коде отсутствуют. Подсветка чисел в `MathText` разбивает строку и выводит фрагменты как текст.
- **Инъекции.** SQL/командных интерпретаторов в рантайме нет; IndexedDB используется через Dexie с типизированными объектами. SymPy запускается только при сборке контента на машине разработчика над сгенерированными шаблонами, не над пользовательским вводом.
- **Хранение пароля.** PBKDF2-SHA-256, 100 000 итераций, случайная соль 16 байт; пароль в открытом виде нигде не сохраняется и не логируется.
- **Сторонние запросы.** Клиент обращается только к своему origin (`content/tasks.json.gz`) и, если задан, к `VITE_SYNC_URL`. Внешней аналитики, трекеров, CDN нет; шрифты упакованы локально.
- **Секреты в репозитории.** Ключей, токенов, паролей нет; `.env` в `.gitignore`, есть только `.env.example`.
- **Загрузка/скачивание.** Экспорт — локальный Blob без обращения к сети; печать в PDF — штатный диалог браузера.

## Что осталось вне кода (нужно на хостинге/сервере)

1. **Аутентификация синхронизации.** `sync-handler.ts` по-прежнему доверяет заголовку `X-Learner-Id`. Его нельзя публиковать без внешней аутентификации (подписанный токен, auth провайдера), иначе любой, кто угадает id, прочитает или перезапишет чужой прогресс. В файле это прямо описано.
2. **Заголовки ответа.** На хостинге добавить `X-Frame-Options: DENY` (или `frame-ancestors 'none'` в CSP-заголовке), `X-Content-Type-Options: nosniff`, `Strict-Transport-Security`, `Permissions-Policy`. Через `<meta>` их задать нельзя.
3. **Локальный аккаунт ≠ защита данных на устройстве.** Регистрация защищает от случайного входа, но IndexedDB доступна любому, кто имеет доступ к профилю браузера. Это свойство local-first архитектуры; для реальной защиты нужен сервер с учётными записями.
4. **Ограничение частоты запросов** к серверу синхронизации (rate limiting) — на уровне провайдера.
