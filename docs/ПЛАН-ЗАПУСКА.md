# Эврика — план запуска для заказчика

Дата: 15 октября 2026 г.

Сайт готов к публикации: его можно выложить на GitHub и открыть ученикам в тот
же день бесплатно. Дальше по шагам подключаются сервер с общей базой, приём
оплаты и домен. Ниже — что уже есть, что делать по порядку, сколько это стоит
и что потребуется от вас.

## 1. Что уже готово

- **Стартовая страница** с описанием сервиса, плюсами и тарифами. В шапке кнопки
  «Войти» и «Использовать»: вторая открывает приложение без аккаунта (гостевой
  режим), прогресс гостя позже переносится в аккаунт одной кнопкой в профиле.
- **Аккаунты по имени**: регистрация без почты, имя должно быть свободно
  (проверяется по базе прямо при вводе), плюс пароль. Вход по имени с любого
  устройства, прогресс подтягивается с сервера.
- **Путеводитель** по интерфейсу при первом входе: 12 подсказок к карточкам и
  вкладкам, можно пропустить и повторить из раздела «Помощь».
- **Сайт целиком**: регистрация и вход, подарок при первом входе (максимальная
  подписка на 30 дней), стартовый тест на 6 задач с баллом по шкале 19, полная
  диагностика на 19 заданий без таймера, индивидуальный план на неделю, тренировки
  по 19 номерам первой части ОГЭ с подсказками и разбором, дуэли, лиги, стрики,
  вызов «100 дней», справочник формул с заметками об ошибках, подписки в профиле.
- **Банк заданий**: 2 140 задач по всем 19 номерам, собранных из 142 шаблонов
  и 2 сюжетов для заданий 1–5 (листы бумаги, шины). Все числа генерируются, каждый
  ответ проверен математически. Около 700 задач с рисунками, 240 с таблицами.
  Чужие тексты не используются.
- **Телефон**: интерфейс проверен на экране 375 px, сайт ставится на домашний
  экран Android и iPhone как приложение, после первого открытия работает офлайн.
- **Сервер аккаунтов** (`server/`): имя для входа, хэш пароля и прогресс в файле
  `users.json`; синхронизация между устройствами. Нужен хостинг с Node.js.
- **Документация** в папке `docs/` и файл `ЗАПУСК.md`: запуск, база данных,
  подписки и приём оплаты, обзор безопасности.

## 2. Шаг 1. Публикация на GitHub Pages — бесплатно, около 15 минут

1. Зарегистрируйтесь на github.com и создайте новый репозиторий (кнопка
   **New repository**, имя любое, например `evrika`, видимость можно Private).
2. На компьютере с проектом выполните в папке проекта:

```bash
git remote add origin https://github.com/<логин>/<репозиторий>.git
```

```bash
git push -u origin main
```

3. В репозитории откройте **Settings → Pages** и в поле **Source** выберите
   **GitHub Actions**. Это делается один раз.
4. Откройте вкладку **Actions** и дождитесь зелёной галочки у «Deploy to GitHub
   Pages» (2–3 минуты). Адрес сайта: `https://<логин>.github.io/<репозиторий>/`.
   Каждое следующее изменение в коде публикуется автоматически после `git push`.

Что работает в этом варианте: всё, кроме общей базы пользователей. Аккаунт и
прогресс каждого ученика хранятся в его браузере, в настройках так и написано:
«Сервер аккаунтов не подключён». Войти в тот же аккаунт с другого устройства
пока нельзя. Этого достаточно для показа, пилота с первыми учениками и сбора
отзывов.

## 3. Шаг 2. Проверка после публикации — 20 минут

Пройдите по чек‑листу на компьютере и на телефоне:

- [ ] Открывается адрес сайта, видна надпись «Эврика — твой личный тренер по ОГЭ».
- [ ] Регистрация: имя и пароль из 8+ символов с буквами и цифрами; занятое имя не принимается.
- [ ] Кнопка «Использовать» на стартовой странице открывает приложение без аккаунта; в профиле
      гостя есть «Создать аккаунт», после которого прогресс сохраняется.
- [ ] После регистрации показан экран подарка с конфетти и датой окончания.
- [ ] Стартовый тест: 6 задач, таймер 7 минут, в конце балл из 19 и разбивка по
      четырём блокам.
- [ ] Главная: план на сегодня, карточка стартового теста, карточка полной
      диагностики.
- [ ] Тренировка из плана: 5 задач, подсказка, разбор после ответа, итог.
- [ ] Задание с рисунком (например, тема 18) и с таблицей (тема 1–5) читаются.
- [ ] Дуэль с одноклассником, лига на вкладке «Дуэли».
- [ ] Профиль → «Подписка»: виден подарочный тариф, младшие тарифы помечены
      «Входит в ваш тариф».
- [ ] Путеводитель на главной после стартового теста: 12 шагов, «Пропустить»,
      повтор через Профиль → Помощь.
- [ ] Вход на другом устройстве под тем же именем показывает тот же прогресс
      (только при подключённом сервере).
- [ ] Телефон: сайт добавляется на домашний экран, после первого открытия
      работает без интернета.
- [ ] Прямая ссылка на внутреннюю страницу (например, `…/plan`) открывается после
      обновления страницы.

## 4. Шаг 3. Сервер аккаунтов, общая база и домен — когда появятся первые ученики

Зачем: чтобы ученик входил с любого устройства, а у вас был список
пользователей и их прогресс в одном месте.

1. Выберите хостинг с Node.js или Docker: Render, Railway, Fly.io, Timeweb Cloud
   или любой VPS. В проекте есть `Dockerfile`, сервис собирается из репозитория
   GitHub автоматически. Папку `/data` нужно сделать постоянным диском — там
   лежит `users.json`. На бесплатных тарифах диск не сохраняется между
   перезапусками, поэтому нужен платный тариф или VPS.
2. Задайте серверу переменную окружения `CORS_ORIGIN=https://<логин>.github.io`.
3. В репозитории откройте **Settings → Secrets and variables → Actions →
   Variables**, добавьте переменную `API_URL` со значением
   `https://<адрес-сервера>/api` и запустите публикацию заново (вкладка Actions →
   «Run workflow»). С этого момента новые аккаунты хранятся на сервере.
4. Настройте резервное копирование файла `users.json` (хотя бы ежедневная копия):
   в нём все пользователи.
5. Домен (по желанию): купите домен, в DNS добавьте запись CNAME на
   `<логин>.github.io`, в **Settings → Pages → Custom domain** укажите домен и
   включите «Enforce HTTPS». Сертификат GitHub выдаёт сам.

Альтернатива проще в сопровождении: разместить на этом же хостинге весь сайт
целиком (Docker‑образ раздаёт и сайт, и сервер), тогда GitHub остаётся только
хранилищем кода, а хостинг пересобирает сервис при каждом пуше.

## 5. Шаг 4. Приём оплаты — после появления юрлица

Сейчас кнопки «Оформить» работают как заглушка: тариф включается в демо‑режиме,
денег никто не платит. Для реальной оплаты:

1. ИП или ООО, расчётный счёт. На сайте нужны оферта, политика конфиденциальности
   и описание тарифов с ценами.
2. Регистрация в платёжном сервисе: ЮKassa (рекомендуется), CloudPayments,
   Robokassa или Т‑Банк Эквайринг. Включить автоплатежи для ежемесячного списания.
   Комиссия около 3 % с платежа.
3. Интеграция: 1–2 рабочих дня после доступа к кабинету — создание платежа,
   вебхук подтверждения, автопродление, проверка тестовыми платежами.
   Подробно в `docs/ПОДПИСКИ.md`.

## 6. Сроки, стоимость, что нужно от вас, риски

| Этап | Срок | Стоимость | Что нужно от заказчика |
| --- | --- | --- | --- |
| GitHub Pages | 15 минут | 0 ₽ | Аккаунт GitHub |
| Проверка | 20 минут | 0 ₽ | Телефон и компьютер |
| Сервер и общая база | 1–2 часа | от 250 ₽/мес (VPS) или 5–7 $/мес (Render, Railway) | Аккаунт на хостинге, карта для оплаты |
| Домен | 30 минут | 300–1 000 ₽/год | Выбор имени домена |
| Приём оплаты | 1–2 рабочих дня | комиссия ≈ 3 % | ИП/ООО, оферта, доступ к кабинету ЮKassa |

Ограничения, о которых стоит знать заранее:

- **Восстановление пароля** пока не реализовано, а почты у аккаунтов нет. Варианты:
  код восстановления, который показывается при регистрации, или сброс пароля
  администратором по запросу. Около одного дня работы.
- **Гостевой режим**: прогресс гостя живёт только в браузере, очистка данных
  браузера его удаляет. Напоминание «Создать аккаунт» есть в профиле и в
  настройках.
- **Админ‑панели нет**: список пользователей смотрится прямо в `users.json`.
  Простая панель с выгрузкой в таблицу — около одного дня работы.
- **Файл вместо СУБД** рассчитан на сотни учеников. При тысячах активных
  пользователей нужен переход на PostgreSQL, код к этому готов (меняются две
  функции в `server/index.ts`).
- **Банк заданий** можно расширять: новые сюжеты для заданий 1–5 (квартира,
  участок, тарифы, печь) добавляются из ваших выгрузок тем же конвейером,
  примерно полдня на сюжет.
- **Офлайн‑режим** на GitHub Pages стоит проверить один раз после публикации:
  в среде разработки его не удалось протестировать.
