# Эврика — инструкция по запуску

Сайт собран на Vite + React. Аккаунты (уникальное имя, хэш пароля) и прогресс по темам
хранятся на сервере в файле `server/data/users.json` в виде списка пользователей;
сервер — один файл `server/index.ts` на Node.js без дополнительных зависимостей.
Он же раздаёт собранный сайт, поэтому для запуска достаточно Node.js.

## 1. Что установить

- **Node.js** версии 24 (LTS) — https://nodejs.org. Подойдёт и 22.18 или новее,
  более старые версии не запустят сервер. Вместе с Node ставится `npm`.
- Проверка в терминале (PowerShell, Terminal или командная строка):

```bash
node -v
```

Python нужен только для необязательной проверки банка заданий (см. раздел 5).

## 2. Распаковка

Распакуйте архив `Эврика-project.zip` в любую папку без кириллицы и пробелов в
пути, например `C:\projects\evrika` или `~/projects/evrika`. Дальше все команды
выполняются из этой папки:

```bash
cd C:\projects\evrika\For_C_C
```

## 3. Установка зависимостей (один раз)

```bash
npm install
```

Занимает 1–3 минуты, появится папка `node_modules`.

## 4. Запуск для просмотра (режим разработки)

```bash
npm run dev
```

Одна команда запускает и сайт, и сервер аккаунтов (он поднимается на порту 8787
автоматически). В терминале появится адрес, обычно `http://localhost:5173`.
Откройте его в браузере. Чтобы остановить, нажмите `Ctrl + C`.

Если нужен только сервер аккаунтов (например, для проверки API), его можно
запустить отдельно: `npm run server`.

Чтобы открыть сайт с телефона в той же сети, запустите:

```bash
npm run dev -- --host
```

и перейдите по адресу вида `http://192.168.x.x:5173`, который напечатает терминал.

## 5. Сборка для размещения на хостинге

```bash
npm run build
```

Команда пересобирает банк заданий, проверяет типы и кладёт готовый сайт в папку
`dist`. Проверить сборку локально:

```bash
npm run preview
```

Откроется `http://localhost:4173`.

Затем запустите готовый сайт вместе с сервером аккаунтов одной командой:

```bash
npm start
```

Сайт откроется на `http://localhost:8787` (порт меняется переменной `PORT`,
путь к файлу пользователей — переменной `DATA_FILE`). Этот процесс можно
разместить на любом VPS или платформе с Node.js (Render, Railway, Timeweb и т. п.):
команда запуска — `npm start`, перед ней — `npm install` и `npm run build`.
Файл `server/data/users.json` создаётся сам при первой регистрации; делайте его
резервные копии, в нём все пользователи.

Если нужен только статический хостинг (Netlify, Vercel, GitHub Pages), загрузите
папку `dist`, а сервер `server/index.ts` разместите отдельно и укажите его адрес
в `.env` как `VITE_API_URL=https://адрес-сервера/api` перед сборкой. Все адреса
вида `/plan`, `/topics/...` должны отдавать `index.html` (настройка «SPA fallback»).

Сайт работает офлайн после первого открытия: установлен service worker, который
кэширует приложение и банк заданий.

Необязательная проверка банка заданий (нужен Python 3 с пакетом `sympy`):

```bash
npm run validate
```

## 7. Как устроены аккаунты

- Регистрация: уникальное имя и пароль (не короче 8 символов, буквы и цифры); почта
  не нужна. Имя проверяется по базе: занятое имя взять нельзя.
- Гостевой режим: кнопка «Использовать» на стартовой странице открывает приложение
  без аккаунта. Прогресс гостя хранится на устройстве; в профиле есть кнопка «Создать
  аккаунт», после которой весь прогресс переходит в аккаунт.
- В `users.json` хранится хэш пароля (PBKDF2‑SHA‑256, 100 000 итераций), а не сам пароль.
- Прогресс по темам, попытки, карточки, дуэли и результаты диагностик синхронизируются
  с сервером каждые две минуты и при входе; вход возможен с любого устройства.
- Без связи с сервером сайт продолжает работать: прогресс копится на устройстве и
  отправляется при следующем подключении. Войти офлайн может пользователь, который
  уже входил на этом устройстве.
- После 10 неверных паролей подряд вход блокируется на 15 минут.

## 8. Первый запуск для ученика

После регистрации ученик обязательно проходит стартовый тест: 6 задач с выбором
ответа за 7 минут (2 по алгебре, 1 по теории вероятностей, 1 на прогрессии,
2 по геометрии). Результат переводится в шкалу первой части: 19 · верных / 6,
с округлением вверх (например, 4 верных → 13 баллов из 19). Тест можно проходить
повторно; он подстраивает план, пока не пройдена полная диагностика на 19 заданий,
после неё план строится только по ней. Полная диагностика без таймера доступна
с главного экрана и необязательна.

## 9. Подписки

В профиле есть раздел «Подписка»: бесплатная (12 уроков в месяц), стандартная
(103 ₽, 60 уроков) и максимальная (148 ₽, без ограничений). При регистрации
дарится максимальная подписка на 30 дней. Оплата пока заглушка: тариф включается
в демо‑режиме. Как подключить реальный приём денег — в `docs/ПОДПИСКИ.md`.

## 10. GitHub и хостинг

Проект можно выложить на GitHub как есть: секретов в коде нет, файл с
пользователями `server/data/users.json` и `.env` в репозиторий не попадают
(они в `.gitignore`). После `git clone` достаточно `npm install` и `npm run dev`:
банк заданий собирается автоматически.

### Публикация на GitHub Pages (бесплатно, без сервера)

В репозитории есть готовый сценарий `.github/workflows/pages.yml`: при каждом
пуше в ветку `main` сайт собирается и публикуется сам.

1. Создайте репозиторий на GitHub и отправьте в него код:

```bash
git remote add origin https://github.com/<логин>/<репозиторий>.git
```

```bash
git push -u origin main
```

2. В репозитории откройте **Settings → Pages** и в поле **Source** выберите
   **GitHub Actions** (один раз).
3. Во вкладке **Actions** дождитесь зелёной галочки у «Deploy to GitHub Pages»
   (2–3 минуты). Адрес сайта: `https://<логин>.github.io/<репозиторий>/`.

Что при этом работает: всё, кроме общей базы пользователей. Регистрация, вход,
стартовый тест, план, тренировки, дуэли и подписки работают, но аккаунт и
прогресс хранятся в браузере ученика (на GitHub Pages нельзя запустить сервер).
В настройках так и написано: «Сервер аккаунтов не подключён». Вход с другого
устройства в тот же аккаунт на этом этапе невозможен.

### Как позже включить общую базу

1. Разверните сервер на хостинге с Node.js или Docker (Render, Railway, Fly.io,
   Timeweb Cloud, любой VPS). В репозитории есть `Dockerfile`: сервис собирает сайт
   и запускает `node server/index.ts` на порту `8787`; папку `/data` нужно сделать
   постоянным диском (там лежит `users.json`). Без Docker: команда сборки
   `npm install && npm run build`, команда запуска `npm start`, Node 24.
   На бесплатных тарифах диск обычно не сохраняется между перезапусками —
   для `users.json` нужен тариф с постоянным диском или VPS.
2. Задайте серверу переменную окружения `CORS_ORIGIN=https://<логин>.github.io`.
   Если сервер стоит за прокси или балансировщиком (Render, Railway, nginx), добавьте
   `TRUST_PROXY=1`, чтобы ограничения на число попыток входа считались по адресу
   ученика, а не прокси.
3. В репозитории откройте **Settings → Secrets and variables → Actions →
   Variables** и добавьте переменную `API_URL` со значением
   `https://<адрес-сервера>/api`. Следующий пуш (или кнопка «Run workflow»)
   пересоберёт сайт, и аккаунты начнут храниться на сервере.

Можно и проще: разместить на таком хостинге весь сайт целиком (тот же Docker‑образ
раздаёт и сайт, и API), тогда GitHub остаётся только хранилищем кода, а хостинг
сам пересобирает сервис при каждом пуше.

## 11. Если что‑то не работает

- `npm: command not found` — Node.js не установлен или терминал открыт до установки;
  переоткройте терминал.
- Порт 5173 занят — Vite сам предложит следующий свободный порт, смотрите адрес в
  терминале.
- При регистрации пишет «Сервер аккаунтов недоступен» — в разработке перезапустите
  `npm run dev` (сервер стартует вместе с ним), на хостинге проверьте, что процесс
  `npm start` запущен и адрес в `VITE_API_URL` верный.
- Пустая страница после обновления кода — в браузере откройте DevTools →
  Application → Service Workers → Unregister и обновите страницу: старая версия
  могла остаться в кэше.
- Хочется начать с чистого профиля — Настройки → раздел «Данные» → «Удалить прогресс» или очистите
  данные сайта в браузере.

Подробное описание архитектуры, контента и безопасности — в `README.md` и папке `docs/`.
Пошаговый план запуска для заказчика (GitHub Pages → сервер → оплата → домен, сроки и
стоимость) — в `docs/ПЛАН-ЗАПУСКА.md`.
